# 0.1.7 compatibility validation on macOS 27.2 beta 2

Date: 2026-09-27. Tested source: `b29a90055bb4`, with no source changes during validation.

## Status

The final runs passed all 58 Swift tests with both the default and native SwiftPM backends, plus 32 Python release/packaging tests. Release compilation, native AppKit presentation checks, read-only Shortcuts access and unsigned package creation also passed.

This is a **qualified compatibility result, not full end-to-end certification**. Initial subprocess tests failed before passing on subsequent runs without code changes. The cause remains unresolved. No installed/configured agent was available for live monitoring tests, and no installation, device action, sleep or shutdown was initiated.

This record supplements the [original 0.1.7 release validation](0.1.7-validation.md); it does not replace the signed/notarized release artifact or its checksum.

### Initial subprocess failures

All 10 initially failing cases were in `ProcessRunnerTests` and used `/usr/bin/python3` as a subprocess fixture. The affected checks covered large stdout/stderr capture, concurrent streams, invalid UTF-8, output limits, cancellation, timeout cleanup and inherited descriptors. Several children produced no output before cancellation or timeout, so expected diagnostics and child PIDs were missing. The cancellation test also exceeded its three-second bound.

The native-backend retry reduced the failures to:

- `testActiveCancellationStopsOwnedGroupAndReapsRootPromptly`
- `testExitedRootDoesNotWaitForInheritedPipeDescriptors`

A standalone `/usr/bin/python3` invocation outside `ProcessRunner` succeeded but took 2.780 seconds. Three later standalone invocations took 0.083, 0.090 and 0.071 seconds. The final full suites then passed in approximately 10.27 seconds with the default backend and 10.14 seconds with the native backend.

Python startup latency is a possible contributor, but these observations do not establish the root cause or prove a macOS regression. No source changes, timeout increases or test skips were used to obtain the passing runs. Passing retries do not demonstrate that cold-start instability is fixed.

## Installed-state observations and limits

The default `~/.config/virt-connector/config.json` was absent. Consequently, the read-only CLI `status` command returned exit code 1 with the expected missing-configuration error. A separate `launchctl print` query found no `st.rio.virt-connectord` service in the current user's GUI domain (exit code 113). `/Library/VirtConnector/VirtConnectorAgent.app` was also absent.

The following remain untested:

- Real installation/upgrade, signing, notarization and Gatekeeper acceptance on this OS.
- Registered LaunchAgent startup and live named-service IPC. The automated suite does cover anonymous XPC transport.
- Real display sleep/wake notifications, physical device state, system shutdown and shutdown cancellation.
- Visual rendering inspection, actual keyboard interaction and VoiceOver task execution. Preview assertions are not substitutes for those checks.
- Runtime behavior on other macOS versions or architectures.

No setup, service registration, system configuration change or production device operation was performed.

## Reproduction commands

Run from the repository root in an interactive macOS user session. The test suites use isolated fixtures; the preview links only presentation code.

```sh
swift test --quiet
swift test --build-system native --filter ProcessRunnerTests --quiet
swift test --build-system native --quiet
python3 -B -m unittest scripts/test-release.py scripts/test-packaging.py scripts/test-postinstall.py

swift build -c release --build-system native --triple arm64-apple-macosx13.0

mkdir -p .build/macos27.2-compatibility
swiftc -parse-as-library \
  Sources/VirtConnectorDaemon/AgentInterface.swift \
  Sources/VirtConnectorDaemon/AgentLocalizer.swift \
  scripts/preview-ui.swift -o .build/macos27.2-compatibility/preview-ui
.build/macos27.2-compatibility/preview-ui --check

DIST_DIR="$PWD/.build/macos27.2-compatibility" scripts/build-pkg.sh --unsigned
```

Keep initial failures when recording results; a passing retry alone omits the observed instability. The commands above reproduce the main checks but do not perform installation or the independent package-content assertions described in this record.
