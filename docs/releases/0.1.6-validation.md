## Test-isolation incident and recovery

Before the sandbox protections were added, two initial CLI test runs selected a stale executable. Between approximately 16:28:54 and 16:29:33 JST, setup cases reached the real user's launchd domain despite using temporary configuration/plist paths. The last observed registration pointed to a temporary plist and `/unused/daemon`, leaving the actual monitor stopped.

The original installed plist was still present with its pre-session modification time. The erroneous registration was unloaded and the original installed plist was bootstrapped. The original installed agent was then confirmed running; its PID remained unchanged across the final sandboxed suites. No new release package was installed as part of this recovery.

Direct test Shortcuts/shutdown cases were not reached in the affected runs. However, the stale daemon could have read the real configuration while temporarily running, so indirect event-driven actions during that interval cannot be ruled out. This incident is not represented as an isolated or side-effect-free test run.

## Limits

No full privileged install/upgrade of 0.1.6, real system shutdown/cancellation, or physical device-state test was performed. OS actions in the final regression suite use substitutes or are blocked by the sandbox. The package is explicitly Apple Silicon-only; Intel execution is not claimed.

Process cleanup covers each invocation's owned process group. A descendant that deliberately detaches into a different process group is outside that ownership boundary; inherited output descriptors are still bounded rather than waited on indefinitely. Shortcut success is not an independent confirmation of the physical device state.
