# Virt-Connector 0.1.6 — reliable action execution and coordinated shutdown

Addresses all twelve findings from the [GPT-6 Astra design/code review](https://github.com/rioriost/Virt-Connector/blob/v0.1.6/docs/reviews/2026-09-16-design-code-review.md).

- Drain subprocess stdout and stderr concurrently, bound execution and captured output, and report failures explicitly.
- Preserve existing settings on read/validation errors, share legacy-configuration decoding, and reject invalid CLI options before writing.
- Abort VirtConnector-initiated shutdown when a required Shortcut fails; report device-specific failures and nonzero CLI exit status.
- Coordinate display events, CLI actions, and shutdown through the resident agent's same-user XPC interface. Suppress queued display actions during shutdown and deduplicate shutdown notifications. Connection failures never cause an automatic standalone retry.
- Resume actual monitoring when `enable` follows an upgrade performed while disabled. Pass resolved configuration/log paths into the LaunchAgent.
- Add `virt-connector resume` and the matching menu action for use **after macOS shutdown has been canceled** by another application. They resume event handling but do not cancel an OS shutdown request.
- Restrict signed packages to Apple Silicon, macOS 13 or later, and the startup volume. Keep the source-build Formula explicitly HEAD-only.
- Use a shared release version and verify package metadata before updating the Cask checksum.

Apple-menu shutdown remains best-effort. Shortcut success does not independently verify the physical device state. Existing valid configuration files are retained; legacy files may omit `enabled`, but must include a valid `devices` array.

The release package is signed with Developer ID, notarized, and stapled. See the [validation record](https://github.com/rioriost/Virt-Connector/blob/v0.1.6/docs/releases/0.1.6-validation.md) for checks, limitations, and the initial test-isolation incident and recovery.
